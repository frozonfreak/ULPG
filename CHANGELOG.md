# Changelog

## 0.4.0 — 2026-10-24

Targeted page-experience guidance based on the supplied v0.4 recommendations. Preserve all 20 top-level section numbers and existing sections, including 8.2; add subsections rather than renumbering existing guidance.

- Add 4.5 entry-pattern selection and 4.6 discovery/navigation architecture. Require a rationale grounded in intent, familiarity and purpose and reachable decision-critical information/destinations. Patterns are illustrative and combinable; no hero, search feature or menu structure is universal.
- Clarify 4.2 and 7.3: recognizable products, service-selection interfaces and editorial subjects can communicate the initial message without conventional benefit copy. Replace the initial-viewport “essential proposition” requirement with subject, offering or task; necessary context and information remain required.
- Add first-time/returning considerations in 3 and 8.3. Recommend appropriate persistent navigation or separate routes without requiring accounts, personalization or tracking.
- Add 6.1 and 11.1 demonstration guidance: truthful capabilities, data labels and execution feedback, accessible operation, meaningful static/equivalent fallbacks and relevant enhancement states. Interactive demonstrations remain optional; fallback and state planning are recommendations, while truthful representation and applicable accessibility are requirements.
- Expand 9 with maintenance ownership/triggers in 9.1 and add ongoing verification in 15.4. Recommend appropriate checks for obsolete promotions, prices, features, screenshots, broken demonstrations and discontinued offerings without imposing a refresh interval.
- Clarify 12.1's field/lab distinction using Google's primary documentation: use field evidence when available and lab tests for diagnosis/regressions. Retain WCAG 2.2 AA guidance, Core Web Vitals thresholds, project-specific budgets and all existing neutrality/non-regression safeguards.
- Align the acceptance checklist, workflows, prompts, brief/review/performance templates, worked example, version metadata and documentation checker. Add a fictional same-brief comparison for five scenarios with explicitly limited heuristic coverage judgments.

**Adoption:** Review the new entry-rationale requirement, navigation reachability wording and demonstration-specific requirements when updating a pinned v0.3 baseline. Apply optional features only where justified. These are ULPG design-process changes, not new legal obligations or external standards. Existing brand, accessibility, truthful evidence and project-specific conflict resolution remain applicable; DDM and Web HIG remain independent.

**Validation scope:** Primary WCAG, Web Vitals and PageSpeed Insights references were rechecked on 2026-10-24. The scenario comparison is a heuristic reading of documentation. No implementation, rendered mobile interaction, animation, user study, conversion outcome, laboratory benchmark or field-performance evaluation is claimed. Repository check results are reported separately and do not validate landing pages. No tag or hosted release is implied by this version update.

## 0.3.0 — 2026-10-24

Initial open-source edition, adapted from the supplied *Universal Landing Page Design Guidelines v0.3 — Proposed correction release*.

- Preserve the source's 20 core sections, requirement levels, contextual conflict resolution, and page-type neutrality.
- Rename the public project to Universal Landing Page Guide; retain ULPG.
- Remove temporary correction labels and replace proposal-release framing with explicit edition and validation status.
- Clarify that outcomes and validation methods are separate, and link external claims to primary references.
- Add human and agent workflows, task prompts, five reusable templates, and a fictional worked review.
- Add MIT licensing, provenance, contribution guidance, governance, issue and pull request templates, and documentation checks.

The source describes corrections relative to v0.2, but this repository does not contain or claim to have independently reviewed v0.2. No implementation, user study, WCAG conformance audit, or field-performance evaluation is included in this release.
