# Using ULPG as a person or team

Use this workflow for a new page or an existing page review. The [guide](guide.md) is the baseline; this workflow helps you apply it without prescribing a visual template.

## 1. Write a brief

Copy the [page brief](../templates/page-brief.md). Identify the audience, purpose, decision, important visitor questions, evidence, and constraints. List supported devices and languages. Separate known facts from assumptions.

For an existing page, record the baseline and supported journeys before changing it. For a new page, define observable acceptance criteria before implementation. Choose appropriate outcomes: reading, exploration, contact, or purchase may each be meaningful.

## 2. Plan the information

Map visitor questions to the content needed to answer them. Place material conditions, costs, limitations, and evidence before the decisions they affect. Sketch a content outline before choosing a visual style.

Choose imagery for its job: show the actual product, explain a process, or provide context. A text-first page is valid. Avoid adding testimonials, FAQs, grids, or pricing sections just to fill a template.

Justify the entry pattern using intent, familiarity and purpose (guide 4.5). Choose discovery routes such as search, categories, product families, audience routes or contextual links only when useful (4.6). Consider what first-time visitors need to learn and what returning visitors need to find or resume (8.3); accounts and tracking are optional.

If a demonstration helps explain a capability, plan accurate labels for sample data and simulated actions, meaningful static or equivalent fallback content, and relevant loading/error states (6.1, 11.1). Brand-led or editorial entry can be appropriate without conventional benefit copy.

## 3. Apply the quality baseline

Read the relevant guide sections. Use the existing design system and document consequential adaptations in the [decision record](../templates/decision-record.md). Inventory third-party code with the [script inventory](../templates/third-party-inventory.md). Set measurable targets with the [performance budget](../templates/performance-budget.md).

Resolve applicable obligations and approved project requirements before generic preferences. ULPG alone does not establish legal compliance or WCAG conformance.

## 4. Evaluate what was built

Copy the [review template](../templates/review.md). Inspect the real page at representative viewports and zoom settings. Exercise keyboard navigation, links, buttons, forms, overlays, reduced-motion behavior, and supported localized content where applicable.

Use automated accessibility checks as one source of evidence alongside relevant manual and assistive-technology testing. Record exactly what you tested. For performance, keep laboratory findings separate from field data, and record devices, conditions, time windows, and budgets. For comprehension or conversion, define a research method and success criteria instead of inventing a universal target.

If you only have a screenshot, you can evaluate visible content and hierarchy. You cannot establish keyboard behavior, DOM semantics, responsive reflow, network behavior, or field performance from it.

## 5. Resolve and report

Fix issues in order of visitor impact. Recheck affected journeys and compare with the baseline. Report supported conclusions, open questions, and unverified items. Record a responsible person and next step for unresolved findings.

Pin your adopted guide version or commit. Revisit the review when the offering, claims, languages, scripts, or user journeys change.

Assign a content owner and appropriate freshness triggers or cadence (9.1, 15.4). Recheck changing prices, promotions, features, screenshots, availability, links and demonstrations; record verification sources and unresolved updates.
